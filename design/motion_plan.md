## 七個環節的原始盤點

下面是 09-24 第一版寫的規劃，1–4 已經照著做完、7 取消，
留著是為了記住每一條「為什麼值得做」。實際做出來的參數以程式碼為準
（`web/styles/motion.css`、`web/scripts/shutter.js`、`web/styles/idle.css`）。

### 1. 選項按下 → 換片（最該做的一個）

現在：選項變粉紅 → LCD 閃白 → 圖直接換掉。
問題：閃白和換圖是兩件沒有關係的事，中間少了「相機在動作」。

要做：**快門葉片瞬閉再開**（實作收斂成 140ms 閉、停 40ms、220ms 開——關比開快才像機械快門），
新的圖在葉片後面換好，開的瞬間帶一點曝光過衝（亮度 1.15 → 1.0，200ms）。
按鈕本身給一個 2px 的下壓和回彈。

為什麼值得：這是整站被按最多次的互動（每人至少三次）。

成本：純 CSS ＋ 一個 div。半天。

### 2. 進場開機

現在：讀取畫面淡出，測驗就在那裡了。
要做：LCD 從一條掃描線橫向拉開 → HUD 四角框彈進 → REC 開始閃 → 題目由下浮上（60ms 一個字級）。
順序本身就是在說「這是一台相機，它剛開機」。

成本：CSS ＋ 一個進場 class。半天。

### 3. 選項逐一進場

現在：四個選項一起淡入。
要做：錯開 45ms 依序浮上。這一條改動最小、質感差最多。

成本：三行 CSS。**建議跟 1、2 一起做。**

### 4. 倒數 [ 3 ] → [ 2 ] → [ 1 ]

現在：數字直接換掉，沒人會注意到。
要做：舊數字往上滑出、新數字從下滑入（老式計數器），換的瞬間閃一下琥珀色。
另外在相機邊框加一圈很細的進度弧，走 1/3 → 2/3 → 滿。

成本：小。但**進度感是完成率的直接變數**，值得做。

### 5. 出片（結果頁最高情緒點）

現在：相紙滑出 900ms。
要做三段疊起來：
- 相機輕微後座（下壓 4px 再回彈），出片和拍照的因果對起來
- **顯影**：相紙剛出來時低對比、偏灰、略帶洋紅，1.6 秒內顯影到正常
- 相紙邊緣一道反光掃過（跟背景的掃光同一套語言）

顯影這一段最貼題，拍立得的等待感本來就是這個產品的情緒。

成本：一天。

### 6. 稀有度揭曉

現在：打字機打完就結束。
要做：比例數字從 0 滾到實際值（0% → 12%），滾完英文短句「蓋章」落下（scale 1.4 → 1，帶一點旋轉）。

成本：半天。等稀有度文案定稿再做。

### 7. ~~結果頁場景 5 秒循環~~（09-24 取消）

Jimmy 的判斷：**結果圖的設定是拍貼機吐出來的一張照片，照片不會動。**
要讓場景動起來，得先說服自己「為什麼這張相紙會動」，而這個理由不存在。
原本規劃的四個場景疊層（光束／紙花／霓虹／樹影）整段作廢，
連帶不需要散景 overlay、紙花 PNG、煙霧 PNG 這三樣素材。

留下來的只有一條，因為它跟「會不會動」無關，是「是不是貼紙」的問題：
**人物層 ±0.4% 的呼吸**。這一條之後如果要做，成本是三行 CSS。
