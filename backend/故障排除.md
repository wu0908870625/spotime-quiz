# 網站出問題時怎麼辦

先看症狀，再照那一段做。每一段的第一步都是「先確認是不是真的壞了」，很多時候只是單一手機的網路問題。

整個網站分三塊，壞的地方不一樣，修法也不一樣：

| 這一塊 | 負責什麼 | 壞了會怎樣 |
|---|---|---|
| Cloudflare 靜態檔 | 網頁、圖片、程式 | 網站打不開 |
| Cloudflare Worker（`/api`） | 擋灌票、轉資料給 Google、數流量漏斗 | 網站能玩，但資料進不了試算表 |
| Google Apps Script ＋ 試算表 | 存作答、存 email、算稀有度 | 同上；稀有度改用估計值 |

---

## 0. 三十秒健康檢查

手機或電腦打開這個網址（正式站把 `spotime-quiz-preview` 換成 `spotime-quiz`）：

```
https://spotime-quiz-preview.spotime.workers.dev/api?all=1
```

| 看到什麼 | 代表 |
|---|---|
| `{"total":64,"counts":{…}}` 這種字 | Worker 和 Google 都正常 |
| `{"error":"upstream failed"}` | Worker 正常，**Google 那邊有問題** → 看第 3 段 |
| `{"error":"too many requests"}` | 你自己一分鐘內按太多次，等一分鐘再試 |
| Cloudflare 的錯誤頁，寫著 `1027` | **Cloudflare 免費額度用完** → 看第 2 段 |
| 整頁打不開 | 看第 1 段 |

---

## 1. 網站打不開，或一直停在 LOADING

1. **換一支手機、換網路（Wi-Fi ↔ 行動網路）再開一次。** 只有一支打不開，多半是那支手機的問題。
2. 看 Cloudflare 本身有沒有出事：<https://www.cloudflarestatus.com>。有的話只能等它修好。
3. 如果是**剛部署完**才壞的，退回上一版：
   - Cloudflare 後台 → **Workers & Pages** → 點 `spotime-quiz` → **Deployments**
   - 找到上一個正常的版本，按右邊 **⋯** → **Rollback**
   - 退回之後網站馬上會變回舊版
   - ⚠️ 10-06 起加了流量漏斗（新的 Durable Object），**沒辦法退回到 10-06 以前的版本**，按了會顯示不能退。這時候請 Claude 用備份重新部署。
4. 讀取畫面 12 秒還沒好會顯示「網路有點慢，再等一下下」，30 秒會變成「還是載不出來，重新整理試試看」。只有少數人遇到的話，多半是手機網路太慢，重新整理就好；很多人同時遇到才是網站的問題，照上面 1～3 做。

## 2. 能玩，但試算表沒有新資料、email 一直「送出失敗」

### 先判斷是哪一邊

做第 0 段的健康檢查。

### 2-1. 看到 1027：Cloudflare 免費額度用完

- 免費方案每天 10 萬次，**台北時間早上 8 點歸零**。網頁照樣能玩，只是資料進不來。
- 用量在 Cloudflare 後台 → **Workers & Pages** → 首頁右邊的 **Usage**（用量）。
- **馬上能做的：** 升級 Workers Paid（每月 5 美元）。後台 → **Workers & Pages** → **Plans** → Workers Paid。升級後幾分鐘內就恢復，不用改程式、不用重新部署。
- 12/1 這種大日子，建議**前一週就先升級**，不要等到爆掉。

### 2-2. 看到 upstream failed：Google 那邊有問題

1. 打開 Apps Script 專案 → 左邊 **執行項目**（▶ 的圖示）。
2. 看最上面幾筆的狀態：
   - **全部「已完成」**：Google 只是慢，等十分鐘再測一次。
   - **一直「失敗」**：點開那一筆看錯誤訊息，常見的有：

| 錯誤訊息（關鍵字） | 原因 | 怎麼修 |
|---|---|---|
| `forbidden` | 通行碼對不上 | 專案設定 → 指令碼屬性 → `PROXY_TOKEN` 要跟 Cloudflare 那邊一樣。不確定的話**先把這個屬性刪掉**，網站就能先恢復（只是少了一層保護） |
| `Service invoked too many times` | Google 一天的額度用完 | 只能等隔天，或請 Claude 改成少打 Google |
| `Exception: … 權限` / `Authorization` | Google 帳號的授權被收回 | 在編輯器上方選 `setup` → 按「執行」→ 照畫面重新授權 |
| `找不到` / 某個分頁名稱 | 有人改了試算表的分頁名稱 | 分頁名稱改回 `作答結果`、`Email訂閱名單`、`流量漏斗` |

3. 如果是**剛部署新版 Apps Script** 才壞的，退回上一版：
   - 右上 **部署** → **管理部署作業** → 點鉛筆 → **版本**選上一個號碼 → **部署**
   - 網址不會變，網站不用動。

## 3. 試算表的資料怪怪的

| 狀況 | 怎麼修 |
|---|---|
| 欄位對不上（例如造型欄出現場景） | 有人在試算表裡插了欄或刪了欄。**不要在「作答結果」「Email訂閱名單」的資料區插欄、刪欄**；要加自己的欄，加在最右邊。改壞了用 **檔案 → 版本記錄** 回到改之前 |
| 同一個 email 出現兩次 | 偶爾會發生（兩次送出剛好同時到），匯出名單時去重就好 |
| 「組合統計」變成 `#REF!` | A1 的公式被改到了，貼回這行：`=QUERY('作答結果'!G:G,"select G, count(G) where G is not null group by G order by count(G) desc label G '組合', count(G) '次數'",1)` |
| 「流量漏斗」超過一小時沒更新 | 第 10 版 Apps Script 還沒部署的話本來就不會更新；部署過的話，看第 2-2 段 |

---

## 4. 真的搞不定的時候

把下面這些貼給 Claude，它能直接接手：

1. 第 0 段健康檢查看到的那行字
2. Apps Script「執行項目」最上面那筆的錯誤訊息（截圖也可以）
3. 什麼時候開始壞的、那之前有沒有人改過網站或試算表

**資料不會因為網站壞掉而消失：** 已經寫進試算表的都還在。壞掉的那段時間裡新進來的作答和 email 會漏掉，修好之後不會自己補回來。
